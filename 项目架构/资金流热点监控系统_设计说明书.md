# A股板块资金流 / 热点生命周期监控系统 — 技术设计说明书

> 版本 v0.1（设计蓝图）｜定位：在现有 QuantFlow 的 board 模块之上**扩展**，不重建。
> 核心原则：**先验证 Alpha，再进评分；先建回测，再上信号。** 权重不许拍脑袋。

---

## 0. 设计约束（从踩过的坑固化为硬约束）

这些不是可选项，是设计前提：

1. **"主力资金"数据不可信**：东财/AKShare 的主力净额是**按单笔成交额大小推断**的，非真实机构流向，噪声大、可对倒骗线。→ 资金流维度**降级为一个弱信号**，且优先用更硬的代理（北向、龙虎榜、涨停封单、ETF 溢价）。任何资金类 Feature 必须标可靠性且经回测才可入评分。
2. **指标共线 = 重复计分**：板块涨幅 / RS / 赚钱效应 / 创新高本质都是"在涨"。→ 评分**拆成正交子分**（动量 / 广度 / 资金 / 龙头），不揉成一个 100 分。
3. **"提前"要靠领先指标兑现**：多数传统指标是确认/滞后。→ Feature Dictionary 强制标 `领先/确认/滞后`，报告的"新增热点"只能由**领先+确认**触发，不能只由滞后指标点亮。
4. **板块归属重叠**：一只票挂多个概念，板块聚合会重复统计。→ 聚合层必须做**去重/归属**（见 §3.4）。
5. **东财板块数据脆弱**（日K限流、成分不全）：已有 `board_synth_daily` 合成指数兜底。→ 板块行情一律走"合成优先"三级数据源（§7）。
6. **不做全局 `db.create_all()`**：新表沿用现有 `ensure_table()` 惰性建表 + `__bind_key__='quanttradingsystem'`。

## 1. 总体架构

```
                          ┌──────────────────────────────────────────┐
  数据层 (已有)            │ data_stock_daily(含 ss_*) · data/15m/*.parquet          │
  OHLCV/板块/新闻          │ industry_eastmoney(成分+市值) · board_synth_daily(合成指数)│
                          │ news_articles/entities/topics · 龙虎榜/北向/涨停(新接入)   │
                          └───────────────┬──────────────────────────┘
                                          ▼
  特征层 (Feature)         每日为「每个板块」算一组 Feature，写入 eval_board_flow(新)
  领先/确认/滞后 + 可靠性    ── Feature Dictionary 定义每个 Feature 的公式/源/评级
                                          ▼
  评分层 (正交子分)         动量分 · 广度分 · 资金分 · 龙头分（各独立 0-100，回测定权重）
                                          ▼
  状态机层                 市场状态(risk-on/off 门) → 板块生命周期(5阶段) → 轮动方向
                                          ▼
  信号/报告层              每日热点报告：新增/持续/衰退热点 · 资金流入流出 TOP · 风险提示
                                          ▲
  回测层 (贯穿)            对每个 Feature/子分/状态：forward-return IC、分层收益、阶段条件收益、
                          衰减半衰期 → 决定保留/淘汰/权重。**任何东西上线前先过这层。**
```

模块与现有代码的对应见 §6（数据库/服务复用表）。

## 3. Feature Dictionary（特征字典）— 核心产出

每个 Feature 的规范字段：`名称 | 定义 | 公式 | 数据源 | 领先/确认/滞后 | 可靠性 A-D | 现状(复用/新增) | 入哪个子分`。

**可靠性评级**：A=硬数据直接可得且难操纵；B=可得但有噪声；C=推断值/可操纵/口径不稳；D=实验性。
**C/D 级默认不进评分，只做展示或待回测转正。**

### 3.1 动量子分 Features（MOMENTUM）

| 名称 | 公式 | 源 | 时序 | 可靠 | 现状 |
|---|---|---|---|---|---|
| `mom_ret_1/3/5/10` | 板块合成指数 N 日收益率 | board_synth_daily | 滞后 | A | 复用(合成K) |
| `mom_rs` | 板块相对沪深300 的 RS = 板块N日收益 − 指数N日收益 | synth + 000300 | 确认 | A | 新增 |
| `mom_trend_score` | 现有 v1-mtf 板块趋势总分 | eval_board_trend_score.total_score | 确认 | B | ✅复用 |
| `mom_stage` | 现有 v1-mtf 阶段 up_early/… | eval_board_trend_score.trend_stage | 确认 | B | ✅复用 |
| `mom_score_slope` | 趋势分 5 日变化率（评分动量） | eval_board_trend_score 历史 | **领先** | B | 新增 |

> 说明：`mom_score_slope`（评分在提升）比"涨幅"更早，是把滞后分转成领先信号的关键。

### 3.2 广度子分 Features（BREADTH）— 赚钱效应/扩散

| 名称 | 公式 | 源 | 时序 | 可靠 | 现状 |
|---|---|---|---|---|---|
| `bd_adv_ratio` | 板块内上涨家数 / 总家数 | data_stock_daily(成分) | 确认 | A | 新增 |
| `bd_limit_up_cnt` | 板块内涨停家数 | 涨停池快照 | 确认 | A | 新增 |
| `bd_limit_diffuse` | 涨停扩散率 = 今日涨停数 / 5日均涨停数 | 涨停池快照 | **领先** | A | 新增 |
| `bd_new_high_cnt` | 板块内创20/60日新高家数占比 | data_stock_daily | 确认 | A | 新增 |
| `bd_promote_rate` | 连板晋级率 = 今日连板数 / 昨日首板数 | 涨停池快照 | **领先** | A | 新增 |
| `bd_leader_health` | 龙头(板块内最高连板/最强RS股)是否续创新高 | 涨停池+日K | 领先 | B | 新增 |

> `bd_limit_diffuse` 与 `bd_promote_rate` 是**萌芽→发酵**最敏感的领先量，A股实战核心。

### 3.3 资金子分 Features（FLOW）— 全部谨慎

| 名称 | 公式 | 源 | 时序 | 可靠 | 现状 |
|---|---|---|---|---|---|
| `fl_turn_ratio` | 板块成交额 / 5日均成交额（放量倍数） | synth.volume(=成交额合计) | 确认 | A | 新增 |
| `fl_turn_lowpos` | 放量且价格处于60日低位（低位放量） | synth + turn | **领先** | B | 新增 |
| `fl_north` | 北向对板块净买（若口径可得） | 北向快照 | 领先 | C | 新增 |
| `fl_lhb_net` | 板块内个股龙虎榜净买入合计 | 龙虎榜快照 | 确认 | B | 新增 |
| `fl_zt_seal` | 板块涨停封单额合计 / 流通市值 | 涨停池快照 | 领先 | B | 新增 |
| `fl_main_net` | 东财主力净额（**仅辅助展示**） | 东财资金流 | 确认 | **C** | 新增 |

> 决策：资金子分**以 `fl_turn_ratio`(A) + `fl_lhb_net`/`fl_zt_seal`(B) 为主**；`fl_main_net`(C)、`fl_north`(C) 先只展示、进回测验证后再决定是否入分。

### 3.4 板块归属与去重（Feature 计算前置）

- 一只股票可同时属多个概念板块。板块级聚合（家数、涨停、资金）用**成分股最新快照**（`industry_eastmoney` latest-per-board，§5 SQL），但需：
  - **权重口径统一**：市值加权量（资金/成交额）按 `circ_cap` 加权，家数类按等权。
  - **重叠提示**：报告层对"高度重叠板块"（成分 Jaccard>0.7）合并展示或标注，避免 TOP 榜被同一批票的多个概念刷屏。
- 龙头归属：一只连板票只归它的**主线概念**（新闻主题 `news_topics_daily.related_boards` 命中度最高者），避免龙头健康度被多板块重复计。

## 4. 评分层（正交子分，权重回测定）

```
板块日度评分 = f( 动量分, 广度分, 资金分, 龙头分 )
```

- 四个子分**各自独立 0-100**，分别由 §3 的 Feature 归一化合成（子分内部权重也需回测）。
- **不预先给总权重**。总分 = Σ wᵢ·子分ᵢ，其中 `wᵢ` 由 §5 回测（分层收益 + IC）反推，且**分市场状态**（risk-on / risk-off 各一套权重，见 §5.3）。
- 输出写入新表 `eval_board_lifecycle`（§6），字段含四子分 + 总分 + 阶段 + 触发信号。

> 与原 txt 方案的区别：原方案一个 100 分把强相关指标堆一起 → 实质=涨幅榜（滞后）。这里正交 + 领先项 + 回测权重，才可能"提前"。

## 5. 状态机设计

### 5.1 市场状态机（大盘门，risk gate）
状态：`risk_on / neutral / risk_off`。输入：全市场涨跌家数比、成交额、创新高−新低、指数 MA。
作用：**门控**。risk_off 时压制"新增热点"信号、只报防守；risk_on 放开进攻信号。转移带**滞后**（连续2日满足才切换）。

### 5.2 板块生命周期状态机（5 阶段）— 核心
状态：`萌芽 → 发酵 → 主升 → 分化 → 衰退`（+ `休眠`）。**必须有明确判定 + 滞后，防止天天跳。**

| 阶段 | 进入条件（示意，阈值待回测校准） | 主导 Feature |
|---|---|---|
| 萌芽 | 低位放量(`fl_turn_lowpos`) + 涨停扩散`bd_limit_diffuse`>1.5 + `mom_score_slope`>0，但绝对涨幅还小 | 领先项 |
| 发酵 | 连板晋级率`bd_promote_rate`>0.5 + 广度`bd_adv_ratio`>0.6 + 趋势分升破60 | 广度+动量 |
| 主升 | 趋势分>75(strong) + 龙头健康`bd_leader_health` + 放量持续 | 动量+龙头 |
| 分化 | 广度回落(涨停数↓、`bd_adv_ratio`<0.5) 但指数仍高 + RSI>70 | 广度背离 |
| 衰退 | 趋势分下穿60 + `mom_score_slope`<0 + 龙头断板 | 动量转负 |

规则：
- **转移需连续 K 日确认（K=1~2）** + 阶段间只能相邻跃迁或直接跌入衰退（防跳变）。
- 每阶段带**最短停留**（如主升≥2日）避免抖动。
- 阶段 = 报告的语义标签，也是回测的分组维度（§5.3）。

### 5.3 轮动
- 轮动方向 = 资金/评分从"衰退/分化板块"流向"萌芽/发酵板块"的净变化。用板块评分排名的**日间变化矩阵**衡量。
- 输出"资金轮动方向"：从 X 类板块 → Y 类板块。

## 6. 回测框架（最先做，是全系统的地基）

**目的**：每个 Feature / 子分 / 阶段，凭证据决定保留、淘汰、权重、是否"领先"。**没过回测的不许进评分。**

### 6.1 标准验证流程（对每个 Feature）
1. **面板构建**：日期 × 板块 的 Feature 值面板（用 `board_synth_daily` 算板块 forward return）。
2. **前瞻收益**：`fwd_ret_{h}` = 板块合成指数未来 h 日收益（h∈{1,3,5,10}）。
3. **IC**：`IC_h = corr(feature_t, fwd_ret_{t→t+h})`（Spearman）；看均值、IR=mean(IC)/std(IC)、正比例。
4. **分层收益**：按 Feature 分5层，看 Q5−Q1 单调性与多空收益。
5. **领先性检验**：feature 领先 return 的最优滞后（cross-correlation 峰值在 τ<0 才算"领先"）。
6. **阶段条件收益**：分生命周期阶段看 Feature 有效性（有的指标只在发酵期有效）。
7. **衰减/半衰期**：信号出现后超额收益的持续天数。

### 6.2 保留/淘汰标准（示意，可调）
- 保留：`|mean(IC_5)|≥0.03` 且 `IR≥0.3` 且分层单调。
- 领先项资格：cross-corr 峰值 τ<0 且显著。
- 淘汰：IC 不显著或与已有 Feature 相关>0.8（共线冗余）。
- 权重：由分层收益/IC 反推（如 IR 加权），**分市场状态**各拟一套。

### 6.3 结果落库
新表 `eval_feature_backtest`：`feature_name, window_h, ic_mean, ic_ir, layer_spread, lead_lag_tau, decay_days, verdict(keep/drop/lead), run_date`。→ 评分层直接读它取权重，形成"回测驱动配置"。

## 8. 信号 / 每日报告层

报告分区（每区都标**触发它的 Feature + 阶段**，可追溯）：
- **今日资金流入 TOP / 流出 TOP**：按资金子分排序（去重叠后）。
- **新增热点**：生命周期进入`萌芽/发酵` 且由**领先项**触发（不许纯滞后点亮）。
- **持续热点**：`主升`阶段、评分与广度仍健康。
- **衰退热点**：进入`分化/衰退`，给减仓提示。
- **风险提示**：市场状态 risk_off、或龙头断板/广度背离。

输出形态：复用现有 `/board_overview` 页 + 新增"每日热点报告"页/推送（可接现有多渠道推送）。

## 9. 开发路线图（每步先验证后推进，设门槛）

| 阶段 | 交付 | **通过门槛（不过不进下一步）** |
|---|---|---|
| **V0 回测地基** | 回测框架 + Feature 面板 + `eval_feature_backtest` | 至少 3 个 Feature 证明 IC 显著且领先 |
| **V1 热点发现** | Feature 层 + 正交评分 + 生命周期状态机 + 每日报告 | 报告"新增热点"在样本外的 5 日胜率显著 > 基准 |
| **V2 资金轮动** | 轮动矩阵 + 市场状态门 + ETF 映射 | 轮动信号的板块切换带来正向超额 |
| **V3 热点预测** | 用 V1/V2 Feature 训练"萌芽→发酵"跃迁预测（可接现有 RNN） | 预测 vs 事后标注的 precision/recall 达标 |

## 10. 术语 & 命名规范

- Feature 命名：`{子分前缀}_{语义}`，前缀 `mom_/bd_/fl_/ld_`（动量/广度/资金/龙头）。
- 时序标签：每个 Feature 元数据必带 `lead|confirm|lag` 与可靠性 `A-D`。
- 表命名：板块评估类 `eval_board_*`，市场原始快照 `mkt_*`，映射 `*_map`。
- 阶段/信号取值沿用现有常量（`TREND_STAGES`、`SIGNALS`），新增生命周期枚举 `LIFECYCLE=(萌芽,发酵,主升,分化,衰退,休眠)`。

## 附：与原始 txt 方案的关键差异（为什么"高一个层级"）
1. **回测前置**：原方案回测在最后；这里是 V0 地基，权重/领先性全靠证据。
2. **正交子分**：原方案 100 分堆强相关指标≈涨幅榜；这里拆四正交子分。
3. **领先性显式化**：Feature Dictionary 强制标 lead/confirm/lag，报告只由领先+确认触发"新增"。
4. **资金流降级**：把最不可靠的数据从"20分核心"降为"待验证辅助"。
5. **扩展而非重建**：复用 eval_board / 打分 / 合成指数 / 新闻，新增仅 Feature/状态/回测/原始快照表。

### 11.2d 时序热度分 heat_ts（2026-08-23，双口径并存）

**要解决的问题**：`heat_score` 是横截面百分位，算它必须有全市场同期快照，而快照
**不可回补** → 概念板块长期只有一两天样本，判不了持续性。

**换个问法绕开横截面**：这个板块今天的涨幅和成交额，在**它自己过去 N 天**里排第几分位？

    heat_ts = 50 × pct_self(涨跌幅, 250) + 50 × pct_self(成交额, 250)

只要有自己的日K就算得出来 —— 池内概念已有合成指数（回到 2021 年），于是**立刻拥有几年历史**。
表 `mkt_board_heat_ts`（board_code + date 唯一），服务 `board_heat_ts_service`。

| | heat_score（cross 横截面） | heat_ts（self 时序） |
|---|---|---|
| 回答 | 今天 504 个概念里谁最热 | 它比自己平时热多少 |
| 数据源 | mkt_sector_flow_daily（当日快照） | 自己的日K / 合成指数 |
| 可回补 | ❌ 概念补不回来 | ✅ 整段可回补 |
| 覆盖 | 全市场 | 仅 L1 候选池 |
| 受成分池变化影响 | ✅ 分母一变历史排名不可比 | ❌ 只跟自己比 |

**两个口径不可混用、不可画进同一条线。** 页面 `?tab=track` 用「口径」下拉切换，
`build_timeline(basis='cross'|'self')`、`/api/hot_timeline?basis=`、`/api/hot_series?basis=` 都支持。

**日K选源不能只看长度**：早期建的 7 个行业合成指数停在 2026-08-07，比东财日K旧半个月却长十倍，
只按"谁更长"选会让 heat_ts 永远停在旧日期。规则改为**先比新鲜度**（落后超 7 天判为过期源），
新鲜度相当时才选更长的。两条序列基点不同（合成指数自定基期 1000），**绝不拼接**。

**时序口径必须用自己的阈值**：cross 的"在榜"是 TOP20/504≈前4%，self 的门槛是自身历史分位，
严格程度差一个数量级；且时序分位天然均值回归，"连续5天站在自身前20%"几乎无人达到
（实测 sustained 恒为 0）。按 2026-08-23 实测分布（60交易日 × 池内101个板块）定：

| 门槛 | 曾在榜板块 | 最长连续中位 | P75 | ≥5天的板块数 |
|---|---|---|---|---|
| 70 | 98 | 3 | 4 | 17 (17%) |
| 80 | 95 | 2 | 3 | 9 (9%) |

→ `HOT_TS_THRESHOLD=70`、`SUSTAIN_STREAK_TS=5`、`SUSTAIN_RATIO_TS=0.35`。
效果：概念 持续8 / 退潮1 / 间歇6（PCB 最长连续7天、在榜45%），而同期横截面口径只有 2 天样本、全部"样本不足"。

流水线 STEP6 每日增量（幂等，实测 101 个板块全量 4 秒）；候选池页「⑥ 时序热度」按钮手动触发。
